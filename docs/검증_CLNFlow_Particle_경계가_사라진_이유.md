# 검증 — CLN_Flow↔Particle의 위험구간 경계가 "없는" 이유

작성 김시우 · 2026-08-11
관련 `rel_20_tier_table.csv` · JHdaimma `발견_라벨정의가_MicroCrack을_가렸다.md` / `회의자료_라벨확장안_결정요청.md`

> **한 줄: 경계값이 잘못된 게 아니라, `pure` 라벨이 위험구간 안의 파티클 74%를 지웠습니다.**

---

## 1. 무엇이 문제로 보였나

관계DB는 `CLN_Flow ↔ Particle`에 이렇게 적어뒀습니다.

```
tier          T2 (조건부조치)      <- 관계는 인정
alert_usable  False
risk_ratio    0.80
경고          "위험구간 불량률이 정상구간보다 낮음 — 이 경계값으로 경보를 걸면 안 됨"
```

즉 경계 아래쪽(CLN_Flow ≤ 9.722)이 위쪽보다 파티클이 **덜** 난다는 뜻입니다. 방향이
뒤집혀 있으니 그 선으로는 경보를 걸 수 없습니다.

## 2. 같은 경계값을 라벨만 바꿔서 다시 재봤습니다

원본 감시 데이터 10만 샷, 경계값은 DB 값(9.722) 그대로.

| 라벨 | 위험구간 파티클률 | 정상구간 파티클률 | 배수 |
|---|---|---|---|
| `pure` (현재 DB) | 5.00% | 6.47% | **0.77배 (역전)** |
| 이진 (`Particle == 1`) | **19.11%** | 7.63% | **2.51배 (정상)** |

위험구간 1,439샷 / 정상구간 98,561샷.

**경계값은 그대로인데 배수가 0.77 → 2.51로 뒤집힙니다.**

## 3. 왜 그런가 — 위험구간 안을 들여다보면

```
위험구간(CLN_Flow ≤ 9.722) 안의 Particle 샷   275
   ├ Remain_Coat 동반   203샷 (74%)   <- pure 라벨이 "Particle 아님"으로 셈
   └ 단독               72샷
```

`pure` 라벨은 "다른 불량이 하나도 없는 샷"만 그 불량으로 셉니다. 그런데 **세정 실패
구간에서는 파티클이 잔류물과 같이 납니다.** 위험구간 파티클의 74%가 그런 샷이라,
그걸 전부 버리면 위험구간이 오히려 깨끗해 보입니다.

멘토 확정 시나리오가 정확히 그 구조입니다.

```
DP04 = Cleaning Failure -> CLN_Flow 감소 -> Remain_Coat / Particle 증가
                                            └─ 같이 난다 ─┘
```

**한 원인이 두 불량을 동시에 일으키면, `pure` 라벨은 그 관계를 증명하는 샷만 골라서
삭제합니다.** JHdaimma님이 Micro_Crack에서 발견한 것과 같은 현상이고, 이 문서는
Particle 쪽에서 같은 일이 벌어지는 걸 경계값 하나로 다시 확인한 것입니다.

## 4. 그래서 무엇을 했고, 무엇을 안 했나

**했다** — 화면에서 CLN_Flow의 하류 defect를 둘 다 이름으로 부릅니다
(`원인 → Remain_Coat · Particle (위험구간 기준 없음)`). 실측 불량률도 둘 다 겹쳐 그립니다.
이름을 부르는 근거는 관계DB의 `defects` 목록과 tier(T2)이지 경계값이 아닙니다.

**안 했다** — 경계값 9.722으로 파티클 경보를 걸지 않습니다. `alert_usable=False`가
막는 게 정확히 그것이고, 이 문서는 그 판정이 왜 나왔는지를 설명할 뿐 뒤집지 않습니다.
Health Index 점수도 안 건드렸습니다(**당시** 4대 91.9 / 47.6 / 50.8 / 14.5 그대로).
(26.08.11 라벨 확장 이후 DP01은 85.0입니다 — 이 문서의 변경 때문이 아니라 별건입니다.)

## 5. 이 결과가 가리키는 결정

라벨을 이진으로 바꾸면 이 짝의 `risk_ratio`가 0.80 → 2.51 이상으로 정상화되고,
`alert_usable`이 True가 되며, 화면의 `(위험구간 기준 없음)` 꼬리표가 저절로 사라집니다.
**우리 쪽 코드는 한 줄도 안 고쳐도 됩니다** — 관계DB를 단일 출처로 읽고 있어서입니다.

그 결정은 JHdaimma님의 `회의자료_라벨확장안_결정요청.md` 결정란에 걸려 있습니다.
이 문서는 그 회의의 근거 자료로 쓰라고 남깁니다.

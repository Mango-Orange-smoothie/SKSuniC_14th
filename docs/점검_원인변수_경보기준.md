## 1. 지금 경보가 어떻게 켜지나

두 단계로 나뉩니다.

```
① trend_analysis.py   (장비 × 컬럼 × Product × Recipe) 시계열에 CUSUM
                       CUSUM_K = 0.7σ   (이보다 작은 편차는 누적 안 함)
                       CUSUM_H = 4.5σ   (누적합이 넘으면 "지속적 이동" 확정)
                       -> 경보가 난 행만 trend_analysis_results.csv에 쌓임 (52,073행)

② build_health_index  그 로그의 마지막 경보가 최근 며칠 이내인가
                       TREND_WARNING_ACTIVE_WITHIN_DAYS = 1
                       -> early_warning_active (true/false)
```

**경보는 변수에 붙습니다.** defect는 경보를 받지 않습니다 — defect는 "그 변수가 나빠지면
생길 수 있는 결과"의 이름일 뿐입니다.

**상위 4개가 정확히 멘토 확정 시나리오입니다.**

## 3. 문제 — 그걸 boolean 한 칸으로 쓰고 있었습니다 (26.08.11 수정됨, §5)

`early_warning_active`는 **"마지막 경보가 1일 이내인가"** 만 봅니다. 규모를 안 봅니다.

```
28개 조합 중 마지막 경보가 3일 이내인 것 : 26개
=> early_warning_active는 사실상 상시 ON
```

그 결과 화면 사이드바에서 이렇게 보입니다.

```
CLN_Flow      경보  14.5     <- 10,513행 / 54개 그룹 / 39.6일째
Head_Temp     경보  98.2     <-     94행 / 25개 그룹 /  0.6일째
```

**같은 배지였습니다.** 규모가 110배 차이나는데 화면에서 구분이 안 됐습니다.
(지금은 각각 빨간 `경보 40일` / 흐린 `경보 0.6일`로 나뉩니다 — §5.)

margin 0.0%(= 값이 정상값에 정확히 있음)인데 경보 배지가 붙은 조합이 7개 있습니다.
전부 지속일 0.1~1.2일짜리입니다.

| 장비 / 인자 | HI | margin | 지속일 |
|---|---|---|---|
| DP02 CLN_Pressure | 98.9 | 0.9% | 0.1 |
| DP03 CLN_Pressure | 99.6 | 0.2% | 0.1 |
| DP02 CLN_Flow | 99.4 | 0.0% | 0.2 |
| DP01 Laser_Power | 99.1 | 0.4% | 0.2 |
| DP04 Head_Temp | 98.2 | 0.1% | 0.6 |
| DP04 Power_Efficiency | 96.8 | 0.0% | 1.1 |
| DP01 Head_Temp | 96.5 | 0.0% | 1.2 |

54개 Product×Recipe 그룹 중 **하나만** 튀어도 그 (장비, 컬럼) 전체가 "경보 중"이 됩니다.

## 4. 점수는 이미 규모를 봅니다 — 표시만 안 봅니다

Health Index의 추세 페널티는 boolean이 아니라 지속일을 씁니다.

```
maturity = alert_active_days / RECENT_WINDOW_DAYS(14)     (0~1)
페널티    = 1 - TREND_PENALTY_MAX_CUT(0.45) x max(maturity, urgency)
```

그래서 0.1일째 경보는 거의 안 깎이고 39.6일째는 최대폭을 받습니다. **점수는 이미
맞게 나오고 있습니다**(위 표에서 지속일 짧은 것들이 전부 HI 96 이상인 이유).

어긋난 건 **표시와 에이전트**입니다. 둘 다 `early_warning_active`를 boolean으로 읽습니다.

## 5. 반영 (26.08.11 — '가'로 결정)

`early_warning_active`를 없애지 않았습니다. 그 옆에 세기를 같이 실어서, 화면과
에이전트가 "경보 O/X"가 아니라 "얼마나 큰 경보인가"를 말하게 했습니다.

| 안 | 내용 | 결과 |
|---|---|---|
| 가 | 사이드바 배지를 세기 2단계로 (`경보 40일` / `경보 0.6일`) | **반영** |
| 나 | 경보 규모(그룹 수·경보행)를 payload에 추가 | 보류 — '가'로 충분했다 |
| 다 | `TREND_WARNING_ACTIVE_WITHIN_DAYS`를 늘려 짧은 경보를 끔 | 기각 — 진짜 초기 경보도 같이 꺼진다 |

'다'를 기각한 이유: 0.1일째 경보가 노이즈인지 새로 시작된 진짜 이상인지는 **지속일로
구분할 수 없습니다.** DP04 CLN_Flow도 39.6일 전에는 0.1일째였습니다. 끄지 말고 **크기를
같이 보여주는** 방향이 맞습니다.

### 어디서 선을 그었나 — 새 상수를 안 만들었습니다

'가'의 원안은 "지속일 기준 2단계"였는데, 그러면 몇 일에서 자를지를 새로 골라야 합니다.
대신 **점수가 이미 쓰고 있는 값**을 그대로 표시로 보냈습니다(§4의 배율).

```
alert_strength = max(maturity, urgency)          # 0~1, 페널티 배율에 쓰는 그 값
alert_level    = "full"  if strength >= 1.0      # 페널티를 최대폭까지 받은 경보
                 "early" otherwise
```

이러면 배지와 점수가 어긋날 수 없습니다 — 어긋남 자체가 이 문제였습니다.
(`urgency`는 `RECENT_WINDOW_DAYS / 관리한계 도달 예상일`. 실측상 지금은 활성 경보
**44건** 중 urgency가 maturity보다 큰 건이 **0건**이라 결과가 순수 지속일 기준과 같지만,
"방금 떴는데 곧 터지는" 경보가 생기면 그때 자동으로 갈립니다. 26.08.18 재측정에서도
0건은 그대로입니다 — `estimated_days_to_control_limit`이 있는 행 자체가 44건 중 3건뿐입니다.)

갈린 결과에 겹침이 없습니다.

| | 건수 | HI 범위 |
|---|---|---|
| `full` | **9** | 14.5 ~ **54.8** |
| `early` | **35** | **80.7** ~ 99.1 |

(26.08.18 실측. 도입 시점(26.08.11)엔 full 11건 14.5~58.3 / early 65건 67.9~99.6이었고,
변동성 확대 경보를 뺀 26.08.16 이후로 줄었습니다. 겹치지 않는다는 성질은 그대로입니다.)

### 화면·에이전트에서 달라진 것

- 사이드바 배지: `경보`(전부 빨강) → `경보 40일`(빨강, full) / `경보 0.6일`(흐림, early)
- 그룹 헤더 빨간 불: 활성 경보 전부 → `full`만. 총 개수는 툴팁에 남김
  (전부 세면 네 그룹에 다 불이 켜져서 어느 그룹을 펼칠지 못 고름)
- 비교 뷰 범례·`⚠️`: 같은 기준으로 통일
- 에이전트: `🟡`를 `full`일 때만. 도구 결과 문구도 `경보 지속` / `초기 경보`로 갈림
  (`_alert_phrase`) — 도구 결과가 과장이면 프롬프트로 못 막습니다

`early` 경보를 지우지 않는다는 원칙은 그대로입니다. 흐리게 보일 뿐 값과 날짜는 다 남고,
툴팁이 "지속되면 빨갛게 바뀝니다"라고 말합니다.

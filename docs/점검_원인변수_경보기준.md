## 1. 지금 경보가 어떻게 켜지나

두 단계로 나뉩니다.

```
① trend_analysis.py   (장비 × 컬럼 × Product × Recipe) 시계열에 CUSUM
                       CUSUM_K = 0.7σ   (이보다 작은 편차는 누적 안 함)
                       CUSUM_H = 4.5σ   (누적합이 넘으면 "지속적 이동" 확정)
                       -> 경보가 난 행만 trend_analysis_results.csv에 쌓임 (52,073행)

② build_health_index  그 로그의 마지막 경보가 최근 며칠 이내인가
                       TREND_WARNING_ACTIVE_WITHIN_DAYS = 1
                       -> early_warning_active (true/false)
```

**경보는 변수에 붙습니다.** defect는 경보를 받지 않습니다 — defect는 "그 변수가 나빠지면
생길 수 있는 결과"의 이름일 뿐입니다.

**상위 4개가 정확히 멘토 확정 시나리오입니다.**


## 3. 문제 — 그걸 boolean 한 칸으로 쓰고 있습니다

`early_warning_active`는 **"마지막 경보가 1일 이내인가"** 만 봅니다. 규모를 안 봅니다.

```
28개 조합 중 마지막 경보가 3일 이내인 것 : 26개
=> early_warning_active는 사실상 상시 ON
```

그 결과 화면 사이드바에서 이렇게 보입니다.

```
CLN_Flow      경보  14.5     <- 10,513행 / 54개 그룹 / 39.6일째
Head_Temp     경보  98.2     <-     94행 / 25개 그룹 /  0.6일째
```

**같은 배지입니다.** 규모가 110배 차이나는데 화면에서 구분이 안 됩니다.

margin 0.0%(= 값이 정상값에 정확히 있음)인데 경보 배지가 붙은 조합이 7개 있습니다.
전부 지속일 0.1~1.2일짜리입니다.

| 장비 / 인자 | HI | margin | 지속일 |
|---|---|---|---|
| DP02 CLN_Pressure | 98.9 | 0.9% | 0.1 |
| DP03 CLN_Pressure | 99.6 | 0.2% | 0.1 |
| DP02 CLN_Flow | 99.4 | 0.0% | 0.2 |
| DP01 Laser_Power | 99.1 | 0.4% | 0.2 |
| DP04 Head_Temp | 98.2 | 0.1% | 0.6 |
| DP04 Power_Efficiency | 96.8 | 0.0% | 1.1 |
| DP01 Head_Temp | 96.5 | 0.0% | 1.2 |

54개 Product×Recipe 그룹 중 **하나만** 튀어도 그 (장비, 컬럼) 전체가 "경보 중"이 됩니다.

## 4. 점수는 이미 규모를 봅니다 — 표시만 안 봅니다

Health Index의 추세 페널티는 boolean이 아니라 지속일을 씁니다.

```
maturity = alert_active_days / RECENT_WINDOW_DAYS(14)     (0~1)
페널티    = 1 - TREND_PENALTY_MAX_CUT(0.45) x max(maturity, urgency)
```

그래서 0.1일째 경보는 거의 안 깎이고 39.6일째는 최대폭을 받습니다. **점수는 이미
맞게 나오고 있습니다**(위 표에서 지속일 짧은 것들이 전부 HI 96 이상인 이유).

어긋난 건 **표시와 에이전트**입니다. 둘 다 `early_warning_active`를 boolean으로 읽습니다.

## 5. 제안 (아직 반영 안 함 — 판단 필요)

`early_warning_active`를 없애자는 게 아닙니다. 그 옆에 규모를 같이 실어서, 화면과
에이전트가 "경보 O/X"가 아니라 "얼마나 큰 경보인가"를 말하게 하자는 것입니다.

| 안 | 내용 | 비고 |
|---|---|---|
| 가 | 사이드바 배지를 지속일 기준 2단계로 (`경보 40일` / `경보 0.6일`) | 데이터가 이미 있음. 화면만 수정 |
| 나 | 경보 규모(그룹 수·경보행)를 payload에 추가 | `trend_analysis_results.csv` 재집계 필요 |
| 다 | `TREND_WARNING_ACTIVE_WITHIN_DAYS`를 늘려 짧은 경보를 끔 | **비추천** — 진짜 초기 경보도 같이 꺼진다 |

'다'를 비추천하는 이유: 0.1일째 경보가 노이즈인지 새로 시작된 진짜 이상인지는 **지속일로
구분할 수 없습니다.** DP04 CLN_Flow도 39.6일 전에는 0.1일째였습니다. 끄지 말고 **크기를
같이 보여주는** 방향이 맞습니다.

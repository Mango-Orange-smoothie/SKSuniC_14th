## 검증 대상

```python
RandomForestClassifier(n_estimators=200, max_depth=8, class_weight="balanced")
permutation_importance(..., scoring="average_precision", n_repeats=10)
RF_TOP_PCT = 0.25          # 상위 25% = 39개 중 상위 10위
```

| 설정 | 검증 전 근거 | 검증 후 |
|---|---|---|
| `scoring="average_precision"` (PR-AUC) | 주석에만 언급 | ✅ **실측 근거 확보** |
| `permutation_importance` | 없음 | ✅ **교차확인 완료** |
| `max_depth=8` | **없음** | ⚠️ **근거 없음 확인 · 영향은 1건** |
| `RF_TOP_PCT=0.25` | **없음** | 🔴 **여전히 없음** |

# 1. 왜 정확도가 아니라 PR-AUC인가 — **실측 확보**

## 결과

| defect | 불량률 | **RF 정확도** | **"전부 정상" 찍기** | **RF PR-AUC** | 찍기 PR-AUC | 배수 |
|---|---|---|---|---|---|---|
| Chipping | 12.09% | 96.4% | 87.9% | **0.911** | 0.121 | **7.5x** |
| **Micro_Crack** | 7.71% | **85.1%** | **92.3%** 🔴 | **0.381** | 0.077 | **4.9x** |
| **Particle** | 10.69% | **67.2%** | **89.3%** 🔴 | **0.310** | 0.107 | **2.9x** |
| **Remain_Coat** | 4.89% | 90.1% | **95.1%** 🔴 | **0.495** | 0.049 | **10.1x** |

## 해석

**정확도로 채점하면 4개 중 3개에서 모델이 "아무것도 안 하는 것"보다 못하게 나옵니다.**

```
Particle    RF 67.2%   vs   전부 정상이라고 찍기 89.3%    → 22%p 뒤짐
```

**그런데 불량을 찾아내는 능력(PR-AUC)으로 보면 2.9 ~ 10.1배 우수합니다.**

불량이 5~12%로 희귀해서, 정확도는 "전부 정상"이라고 찍는 쪽에 유리한 지표입니다.
**PR-AUC 선택이 이 프로젝트에서 결정적이었다는 근거가 확보됐습니다.**

# 3. `max_depth=8` — 🔴 **근거가 없었습니다**

코드·문서 전체를 검색했으나 **주석 한 줄 없습니다.** `RF_TOP_PCT`, `MIN_N_DATASET` 와
같은 종류의 임의값입니다. 그래서 실측했습니다.

# 4. 🔴 발견 — `Head_Temp` 가 합격선 근처에서 흔들립니다

```
깊이  3  →   5위   통과 ⭕
깊이  6  →   7위   통과 ⭕
깊이  8  →   8위   통과 ⭕      ← 현재 설정. 합격선까지 2계단 여유
깊이 12  →  11위   탈락 ❌      ← 1계단 차이로 떨어짐
무제한   →  10위   통과 ⭕      ← 딱 걸침
```

**깊이 12를 골랐다면 `Head_Temp` 가 T1 → T2 로 내려갑니다.**
불량률 94.7배짜리, 발표 핵심 인자입니다.

## 왜 생겼나 — 임의값 두 개가 겹쳤습니다

```
max_depth = 8         근거 없음
RF_TOP_PCT = 0.25     근거 없음  →  합격선 10위

Head_Temp 순위가 5~11위 사이라 하필 합격선 근처
```

## 심각도 — 세 가지 이유로 크지 않습니다

**① 5개 깊이 중 4개에서 통과합니다.** 12에서만 떨어지고 그것도 10위 vs 11위 한 계단입니다.

**② 통계검정에서는 어느 설정에서도 압도적입니다.**

```
Head_Temp   Cliff's delta +0.873   (합격선 0.2의 4.4배)
            불량률 0.37% → 35.32%  =  94.7배
```

RF 에서 떨어져도 **T1 → T2 일 뿐 표에서 사라지지 않습니다.**

**③ 나머지 10건은 어떤 깊이에서도 결론이 같습니다.** (통과 7 · 탈락 3)

## 고칠 수 있는 방법

| 대안 | 결과 | 평가 |
|---|---|---|
| **여러 깊이로 돌려 순위 평균** | 5·7·8·11·10 → 평균 **8.2위** → 안정적 통과 | ✅ 가장 정직 |
| 합격선을 상위 33%(13위)로 | 전부 통과 | 근거는 여전히 없음 |
| 그대로 두고 문서화 | 이 문서로 설명 | 현재 선택 |

**"하나의 임의값에 결과가 걸리지 않게 여러 설정에서 평균냈다"** 가 가장 방어하기 좋습니다.
**반영은 하지 않았습니다.** 팀 논의가 필요합니다.

# 5. 발표에서 할 말 / 하면 안 되는 말

## ✅ 할 수 있는 말

> **"정확도로 채점했다면 4개 중 3개에서 모델이 '아무것도 안 하는 것'보다
> 못하다고 나왔을 겁니다. 그래서 채점표를 PR-AUC 로 바꿨습니다."**

> **"중요도는 내장값 대신 한 컬럼씩 뒤섞어 성적 하락을 실측했습니다.
> 두 방식으로 다 재봤고 확정 도메인 11건은 결론이 같았습니다."**

> **"깊이는 관례값 8을 썼습니다. 3부터 무제한까지 전부 재봤고
> 11건 중 10건은 어떤 깊이에서도 결론이 같았습니다.
> `Head_Temp` 하나가 합격선 근처에서 흔들리는데, 이 인자는 통계검정에서
> delta 0.873, 불량률 94.7배로 압도적이라 순위와 무관하게 유효인자입니다."**

## ❌ 하면 안 되는 말

```
"과적합을 막기 위해 깊이 8로 제한했습니다"       ← 그렇게 고른 게 아님
"깊이 8이 최적입니다"                          ← 최적 아님. defect 마다 다름
"순열중요도를 써서 결과가 달라졌습니다"           ← 11건 결론 동일
"깊이는 결론에 영향이 없습니다"                  ← 1건이 흔들림
```

**약점을 먼저 말하고 왜 괜찮은지 대는 구조가 가장 강합니다.**

# 6. 남은 것 — `RF_TOP_PCT = 0.25`

**이 값은 여전히 근거가 없습니다.**

```
비율로 바꾼 것까지는 근거가 있음
   고정 top-10 은 후보 수가 다르면 defect 마다 엄격함이 달라짐

"왜 하필 25%인가" 는 근거 없음
   39개 기준 상위 10위.  20% 나 33% 여도 안 될 이유가 없음
```

`Head_Temp` 문제가 이 값과 `max_depth` 두 임의값이 겹쳐서 생긴 것이므로,
**둘 중 하나만 정리해도 해소됩니다.**

# 판정 스윕 (순열중요도 순위)

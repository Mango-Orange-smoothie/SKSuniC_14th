# 회의 자료 — 라벨 확장안, 할까 말까

작성 JHdaimma · 2026-08-11 · **결정 요청**
근거 문서 [검증_라벨확장안_손익.md](검증_라벨확장안_손익.md) · [발견_라벨정의가_MicroCrack을_가렸다.md](발견_라벨정의가_MicroCrack을_가렸다.md)

> **결정할 것은 하나입니다.**
> **`Surface_Roughness` 378배를 지킬 것인가, DP04 Particle을 잡을 것인가.**
>
> 둘 다는 안 됩니다. 이유는 아래 3절에 있습니다.

---

# 1. 배경 — 무엇을 발견했나

## 데이터에 불량 컬럼이 두 종류 있습니다

```
NG_Code       한 판에 이름 하나만        "이 판은 CHIP이다"
이진 컬럼      0/1                      "이 판에 크랙이 있다"
```

**한 판에서 모서리도 깨지고 금도 갔으면, 이름은 하나만 붙습니다.**
그래서 defect마다 밀리는 정도가 다릅니다.

| defect | `NG_Code` | 이진 컬럼 | 배수 |
|---|---|---|---|
| Chipping | 24,175 | 24,175 | **1.00x** — 안 밀림 |
| Remain_Coat | 9,266 | 9,774 | 1.05x |
| **Particle** | 11,296 | 21,371 | **1.89x** |
| **Micro_Crack** | **4,921** | **15,413** | **3.13x** |

**Micro_Crack은 3분의 2가, Particle은 절반 가까이가 다른 이름에 밀려 있습니다.**

## 그래서 지금 이런 일이 생깁니다

```
DP04 = 세정 실패 장비 (멘토 확정)
       Particle + Remain_Coat 둘 다 늘어야 함

  실제 최근 7일 Particle 발생률
     DP01 7.44%   DP02 8.68%   DP03 10.25%   DP04 10.27%  ← 공동 1위

  현재 Particle 점수
     DP01 91.9    DP02 90.9    DP03 54.8     DP04 95.0    ← 가장 건강
```

**공동 1위인데 4대 중 가장 건강한 점수를 받고 있습니다.**

---

# 2. 제안 — 안 '다'

```
① 비교군을 '확실한 정상품'으로            ← 전 defect 공통 (명백한 수정)
② 이진 라벨을 Micro_Crack · Particle 에만  ← Chipping · Remain_Coat 는 그대로
```

**②를 전부에 적용하지 않는 것이 핵심입니다.**
Chipping 분석을 안 건드려야 `Head_Temp`(94.7배)가 T1에 남습니다.

**기준: 단일 라벨이 그 defect를 대표로 잡아주지 못하는 경우에만 이진 컬럼을 쓴다.**

# 3. 얻는 것

| | 내용 |
|---|---|
| **DP04 Particle** | **95.0 → 약 14.5** |
| 멘토 시나리오 | Remain_Coat만 → **Remain_Coat + Particle 둘 다** |
| 경보 불가 | 3건 → **1건** |
| 김시우님 채택 짝 | 7건 → **9건** |
| Micro_Crack | "확정 원인 0건" → **"냉각 유량 감소"** |

## DP04 Particle이 바뀌는 근거

```
CLN_Flow ≤ 9.722 진입 샷
   DP01 0샷 · DP02 0샷 · DP03 0샷 · DP04 1,439샷 (5.67%)

그 구간의 Particle   19.11%   (DP04 평균 7.36% 대비 2.6배)
```

**오직 DP04만 그 구간에서 운전했고, 거기서 파티클이 2.6배 났습니다.**
다른 3대 점수는 안 바뀝니다.

# 4. 대가 — 3건

## 🔴 대가 ① `Surface_Roughness` 378배 → 9.8배

### 두 숫자는 다른 질문에 답합니다

```
표면 거칠기가 정상인 판 100장 중, 파티클이 난 판은?

   파티클이 난 모든 판          →  2~3장
   파티클만 나고 다른 불량 없는 판  →  0.04장  (1만 장에 4장)
```

### 왜 이렇게 차이가 나나

표면이 정상인데도 파티클이 나는 판이 있습니다.
**그런 판은 거의 다 다른 문제도 같이 있습니다.**

```
표면 정상인데 파티클 난 판 100장
   약 98장  →  잔류물 등 다른 불량도 같이 있음
   약  2장  →  파티클만 단독
```

`pure` 방식은 저 98장을 **"파티클 아님"으로 셉니다.**
그래서 정상구간 비율이 0.04%로 떨어지고, 나눈 배수가 378로 튄 것입니다.

```
378배  =  13.16%  ÷  0.04%     ← 분모가 0에 가까워 폭발
9.8배  =  23.54%  ÷  2.40%     ← 분모가 정상
```

**분자(위험구간)는 13% → 23%로 오히려 늘었습니다. 배수가 준 건 분모가 커져서입니다.**

### 무엇이 손해인가

**정확도가 나빠지는 게 아니라, 극적인 숫자를 잃는 것입니다.**

| | 378배 | 9.8배 |
|---|---|---|
| 발표에서 | *"378배!"* — 강렬 | *"9.8배"* — 평범 |
| 엔지니어에게 | *"거칠기만 잡으면 파티클 끝"* — **과장** | *"거칠기 잡으면 대부분 준다"* — 정확 |

**표면이 정상이어도 100장 중 2~3장은 파티클이 납니다.**
378배를 믿고 *"거칠기가 정상이니 안심"* 하면 그 2~3장을 놓칩니다.

---

## 🟡 대가 ② "즉시조치 인자 4개"가 3개가 됩니다

`CLN_Pressure`가 Particle의 원인도 되면서 등급이 내려갑니다.

```
CLN_Pressure  →  Remain_Coat   T1 (6.0배)
              →  Particle      T2 (1.99배)

한 인자가 두 등급을 가질 수 없어 낮은 쪽을 대표로 씁니다
```

**Agent 대답이 이렇게 바뀝니다.**

```
지금    "세정 압력은 즉시조치 인자입니다"
바꾸면  "세정 압력은 조건부조치 인자입니다"
```

**단, 안쪽 기록은 그대로입니다.**

```
tier          T2        ← 대표 등급만 내려감
actionable    true      ← 조치 가능 표시 유지
per_defect
   Remain_Coat  T1      ← 여기는 그대로
   Particle     T2
```

> `CLN_Flow`가 이미 똑같은 이유로 T2입니다.
> **새로 생기는 문제가 아니라 같은 일이 하나 더 생기는 것입니다.**

---

## 🟡 대가 ③ Micro_Crack은 점수를 여전히 못 냅니다

라벨을 고쳐도 **재현성 검사**에서 걸립니다.

```
같은 관계를 두 데이터에서 각각 재봤더니

   감시 데이터(원본)   +0.048   ← 유량이 낮을 때 크랙이 "덜" 남
   검증 데이터(r1)    −0.284   ← 유량이 낮을 때 크랙이 "더" 남

   방향이 서로 반대  →  "재현 실패" 도장
   김시우님 코드가 Health Index에서 제외
```

**왜 반대로 나오나 — 감시 데이터에 크랙이 41건뿐이기 때문입니다.**
10만 장 중 41장이면 방향이 우연히 뒤집힙니다. **표본 문제라 라벨로는 못 고칩니다.**

| | 지금 | 바꾼 뒤 |
|---|---|---|
| *"크랙 원인이 뭐야?"* | "확정 원인 0건" | **"냉각 유량 감소"** ✅ |
| *"DP03 크랙 점수는?"* | 없음 | **여전히 없음** ❌ |

**원인은 말할 수 있고 장비별 감시는 못 합니다. 절반은 나아집니다.**

# 7. 제 의견

**적용하는 쪽을 권합니다.** 이유 두 가지입니다.

**하나 — 지금 값이 틀렸습니다.**
DP04는 세정 실패 장비이고 최근 7일 Particle 공동 1위인데 95.0점입니다.
심사에서 *"세정 실패 장비인데 파티클이 왜 건강한가요"* 를 물으면 답할 말이 없습니다.

**둘 — 378배는 설명하기 어렵습니다.**
*"정상구간에 0.04%밖에 없어서"* 인데, 파고들면 **"단독 불량만 센 결과"** 라고 답해야 합니다.
94.7배(`Head_Temp`)는 그대로 남고, **그 숫자는 스펙 안쪽이라는 더 강한 이야기**를 갖고 있습니다.

**다만 발표까지 시간이 없다면 유지도 방어 가능합니다.**
그 경우 위 문서 3건을 근거로 *"알고 있고 다음 단계를 정해뒀다"* 로 답하면 됩니다.

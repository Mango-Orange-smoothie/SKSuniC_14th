# 유닛 테스트

```bash
python3 -m pytest tests -q
```

45개, 2초. **원자료를 안 읽는다** — 순수 함수에 값을 직접 넣어서 규칙대로 도는지만 본다.

## 왜 따로 있나

지금까지의 검증은 두 종류였다.

| | 무엇을 하나 | 한계 |
|---|---|---|
| `build_health_index.py` 실행 | 산출물 점수가 85.0/47.6/50.8/14.5인지 눈으로 확인 | 전체를 다 돌려야 하고, 틀리면 **어디가** 틀렸는지는 안 나온다 |
| `docs/check_*.py` | 산출물끼리 아귀가 맞는지 교차 검사 | 위와 같음. 파이프라인을 한 번 돌린 뒤라야 의미가 있다 |
| **`tests/` (이것)** | 함수 하나에 값을 넣고 결과를 확인 | 함수 밖(파일 IO, 파이프라인 연결)은 안 본다 |

셋은 대체 관계가 아니다. 위 둘은 그대로 두고, **깨진 지점을 바로 짚는 층**을 아래에 깐 것이다.

## 무엇을 검사하나

CLAUDE.md의 "절대 어길 수 없는 규칙"을 코드로 옮긴 것에 가깝다.

- `test_margin_to_health.py` — 규칙 3·5. margin만으로 점수가 나오는가, **10점 미만이
  관리한계 초과일 때만 나오는가**, 경계에서 식이 이어지는가, 전 구간 단조인가.
  멘토 실측 스펙 margin의 방향 처리(`up`이면 아래쪽은 여유 소진 아님)도 여기.
- `test_relationship_db_rules.py` — 규칙 1·2. `per_defect.alert_usable`이 인자 레벨을
  이기는가, 대표 점수가 경보용의 부분집합인가, **컬럼당 하나를 고를 때 행 순서가 아니라
  tier로 고르는가**.
- `test_baseline_direction_filter.py` — 규칙 6. 도메인과 반대로 학습된 그룹만 빠지고,
  방향이 맞는 그룹과 DB에 없는 짝은 그대로 남는가. 합성 데이터로 `CLN_Flow↔Particle`
  상황을 축소 재현한다.
- `test_binomial_alert.py` — 경보 기준선. k가 정의(P(X≥k) < alpha를 만족하는 최소값)를
  실제로 만족하는가, 평소 비율이 높을수록 기준도 높아지는가.

## 값을 베끼지 않는다

"CLN_Flow의 tier는 T1"처럼 관계DB 값을 적으면 DB가 바뀌는 순간 테스트가 거짓말이 된다
(규칙 1). 그래서 값 대신 **관계**를 적었다 — "T1 짝이 T2 짝보다 먼저 골라진다",
"대표 점수 ⊆ 경보용". DB가 갱신돼도 따라간다.

예외는 하나, `direction_of("CLN_Flow") == "down"`이다. 세정 유량은 낮을수록 위험하다는
건 멘토 확정이고 데이터가 아니라 물리가 정한다. 이게 뒤집히면 코드가 아니라 DB를
의심해야 하므로 값으로 못 박았다.

## 이 테스트가 실제로 잡는지 확인한 방법

통과만으로는 "검사를 하고 있다"는 증거가 안 된다. 코드에 예전 버그 3개를 일부러 다시
심고 돌려봤다.

| 심은 버그 | 잡힌 테스트 |
|---|---|
| `margin_to_health`의 스펙아웃 구간을 평탄화 | `ALARM_BAND_미만은_관리한계_초과일_때만`, `스펙아웃끼리도_순위가_남는다` |
| `_usable_defects`가 `per_defect`를 무시(26.08.08 이전 동작) | `per_defect가_False면_그_짝만_빠진다` 외 1건 |
| 방향 필터에서 `continue` 제거 | `도메인과_반대로_학습된_그룹만_빠진다` 외 1건 |

6개가 빨간불로 바뀌었고, 되돌리니 45개 전부 통과했다.

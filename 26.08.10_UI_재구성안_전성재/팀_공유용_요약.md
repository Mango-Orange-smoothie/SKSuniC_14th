# 팀 채널 붙여넣기용

아래 내용을 그대로 복사해서 카톡/노션에 붙이시면 됩니다.
상세 근거는 같은 폴더의 `색경계_알림기준_정리.html`을 띄워서 보여주세요.

## (짧은 버전 — 카톡용)

화면 색 기준(HI 50/80) 근거를 찾다가 정리한 내용 공유드립니다.

**1. 찾은 것**
`agent.py:614` / `dashboard.html:240` 두 군데서 HI 50/80을 쓰는데, 왜 그 숫자인지 적힌 곳을 못 찾았습니다. 주석·커밋 메시지·문서 다 봤는데 "발생 여부→점수로 바꾼 이유"만 있었습니다. 관리한계 3σ, 티어 0.2, 히트맵 색 눈금은 다 근거가 있어서 여기만 비어 보였습니다.
→ **시우님, 혹시 근거 있으신데 안 적으신 건가요? 있으면 문서에 남기면 좋을 것 같습니다.**

**2. 데이터로 만들어보려다 안 된 것**
관계DB 급등선(`alert_threshold_raw`)을 HI로 환산해봤습니다. **9.2~86.0으로 흩어집니다.**
Surface_Roughness는 HI 86에서 이미 378배 뛰고 CLN_Flow는 9.2까지 가야 뜁니다.
게다가 Head_Temp·Power_Efficiency·Cooling_Flow는 감시 데이터 위험구간 불량률이 **0%**라 R1에만 기댑니다.
→ **모든 인자에 통하는 하나의 경계는 지금 데이터로 못 만듭니다.** 50/80에 근거가 없던 건 원래 못 대는 것이었습니다.

**3. 제안 — 80은 없애고 30 하나만 남깁니다**
```
🟢  기본값 — 경보 없으면 초록      ← 경계를 안 잡음
🟡  추세 경보 켜지면 노랑          ← 숫자 없음
🔴  HI 30 미만                     ← 숫자 하나만, 실측 근거 있음
정렬은 같은 색 안에서 HI 낮은 순 (색이 단계를 나누고 HI가 줄을 세움)
```
초록/노랑이 경보 유무로 갈리므로 **80이 쓰일 자리가 없습니다.** 임의 숫자가 30 하나로 줄어듭니다.

**4. 30의 근거 — DP04 실측 (제 담당 Remain_Coat)**
| 날짜 | HI | 7일 불량률 | 평소 대비 |
|---|---|---|---|
| 2/19 | 79.6 | 1.01배 | 추세 경보 → 🟡 |
| 2/27 | 29.9 | **1.11배** | HI 30 통과 → 🔴 |
| 3/3 | 17.4 | — | **불량률 CUSUM 경보** (실제로 늘었다고 판정) |

→ 노랑이 **13일**, 빨강이 **5일** 먼저 갔습니다.

"불량이 늘었다"를 제가 정하지 않았습니다. **원인 변수 판정에 쓰는 것과 같은 CUSUM(K=0.7σ, H=4.5σ)을 불량률에도 걸었습니다.** HI 30을 지날 때 불량률이 아직 평소의 **1.11배**라, 조치할 시간이 남은 지점입니다. R1이 아니라 감시 데이터입니다.

**대조 (Remain_Coat 4대)**
| 장비 | HI | 불량률 CUSUM | 불량률 변화 |
|---|---|---|---|
| DP04 | 14.5 | **3/3 경보** | 2.81배 |
| DP02 | 98.9 | 없음 | 1.25배 |
| DP03 | 99.6 | 없음 | 1.01배 |
| DP01 | 99.0 | 3/4 경보 | 1.10배 |

**사례 1건이 아니라 4대 대조입니다.** HI가 낮은 DP04만 불량률이 2.81배로 올랐습니다.

**5. 알림도 같이 바꾸면 좋겠습니다**
지금은 HI 30 미만이면 매일 나가서 DP04 기준 89일에 **32통**입니다(39일째 같은 상태라 계속 옴).
**색이 바뀔 때만** 보내면 **2통**이고 둘 다 불량 나기 전입니다.
시우님이 `build_health_index.py:398`에 이미 적어두신 방향입니다 —
*"alert_since가 바뀔 때만 새 알림으로 취급해야 한다"*. 계산은 준비돼 있고 n8n 발송 조건만 상태 기반입니다. (승연님 확인 부탁드립니다)

**6. 한계 — 그대로 밝힙니다**
- 검증한 불량이 **Remain_Coat 하나**입니다. Chipping은 89일에 4건이라 표본이 없습니다
- 대조 3대 중 **DP01에서 CUSUM이 하나 떴습니다**(HI 99.0인데). 불량률은 1.10배로 거의 안 올랐지만 대조가 완전히 깨끗하진 않습니다
- **Particle은 근거로 안 씁니다.** HI 90 이상인 DP02·DP04에서도 불량률 상승이 잡혀 점수와 안 맞습니다. `Particle/CLN_Flow` 짝이 `alert_usable=False`로 막혀 있는 것과 관련 있어 보입니다 — 별도 확인 거리입니다
- 일별 HI는 제가 재계산한 근사입니다(마지막 날 14.2 vs 공식 14.5, 0.3 오차)

**7. 바뀌는 범위**
- `hiColor()` 색 판정 — 경보 유무 반영 + 빨강 경계 50→30, **80 제거**
- n8n 발송 조건 (상태 → 전이)

HI 계산식 / 장비·불량·인자 3단계 / 대시보드 구조 / 멘토 4/4 대조는 **안 건드립니다.**
